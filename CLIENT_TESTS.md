# Проверки собственных функций Battery Client

Тесты запускаются для каждого PR. Выпуск APK зависит от успешного reusable workflow `client-tests.yml`: ошибка unit-теста или Android-теста блокирует сборку/публикацию. Готовый APK дополнительно проверяется на наличие всех 70 английских/русских строк и их привязок, Firebase-конфигурации, сервисов, подписи и package id.

## Логика клиента: Robolectric/JUnit

Тестируется реальный код `TMessagesProj`, не копия его реализации:

- Бинарная локализация: ID → русский/английский текст для настроек, Firebase, диагностики, VPN и медиа; 70 строк дополнительно проверяются в APK.
- Firebase/UnifiedPush: автоматический выбор, явное предпочтение, недоступный дистрибьютор, backoff, сохранение настройки/токена после загрузки, защита от позднего UnifiedPush endpoint и отзыва WebPush, запрет автоматического polling, одноразовая миграция старого fallback и FCM-токена.
- Регистрация push: кэшированный токен не запускает повторную регистрацию 32 аккаунтов; пропущенный аккаунт восстанавливается отдельно; новый токен/тип отправляется через свой контроллер каждого аккаунта.
- Локальные настройки уведомлений: независимая загрузка enabled/sound/vibrate для аккаунтов 0 и 31.
- VLESS: разбор URI/параметров, недопустимые ссылки, локальный authenticated SOCKS5, Reality, WS/gRPC, DNS и TUN; отсутствие mux.
- Прокси: матрица режим/профиль/уже работающий core, остановка в фоне и сохранение SOCKS username/password.
- Медиа/телефон: чтение даты MP4, пустая дата/отсутствующий файл, нормализация телефонных URI.
- Обновлятор и диагностика: сравнение версии/хотфикса, повреждённый тег, независимые данные аккаунта 31, границы индексов.

Только внешние границы (FCM/Play Services, транспорт MTProto, очередь/прокси core) заменяются контролируемыми заглушками. Тесты не авторизуются в Telegram и не обращаются к FCM. В проверке регистрации очередь выполняется синхронно; это проверяет маршрутизацию аккаунтов, но не доказывает отсутствие многопоточных гонок.

Локальный запуск с настроенными JDK17/Android SDK:

```bash
./gradlew -PMG_BUILD_TAG=12.10.6.2 :TMessagesProj_App:testAfatFdArm64HardenedUnitTest --no-daemon
```

## Android Keystore и профили: настоящий эмулятор

`BatteryStorageTests` — отдельное тестовое приложение. Gradle копирует выбранные production-файлы в generated sources без изменения; копии не коммитятся. Оно не использует пользовательский package, release key, сессии Telegram или libbox.

Проверяются AES/GCM через AndroidKeyStore, ciphertext вместо открытого профиля/пароля, восстановление после создания нового store, выбор/удаление/дедупликация профилей, перенос legacy plaintext и legacy списка в atomic encrypted no_backup-файл, стабильность credentials и сохранение режима/статуса.

```bash
./gradlew -PMG_BUILD_TAG=12.10.6.2 :BatteryStorageTests:api30DebugAndroidTest --no-daemon
```

Это проверка реального Android API30 хранилища и структуры прежних данных, а не установка двух полноценных APK клиента поверх друг друга.

## Что остаётся проверять на телефоне

Реальная доставка FCM на прошивках Samsung/Xiaomi при смахнутом приложении и заблокированном экране, переход через системный установщик со всеми сессиями, сетевое подключение VLESS/TUN и системный выбор банковского приложения требуют отдельной проверки на устройстве. Эти тесты не запускаются против личных аккаунтов. Полный визуальный smoke-тест каждого экрана также не заменяется проверкой строк. Покрытие касается собственных функций и ключевых сценариев; весь upstream Telegram тестами этого набора не покрыт.
