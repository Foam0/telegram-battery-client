# Telegram Battery Client

Персональный форк [Mercurygram](https://github.com/Mercurygram/Mercurygram) на базе Telegram Android. Я сделал его для двух основных задач: снизить фоновую нагрузку клиента и встроить VLESS-подключение, которое используется только Telegram и не поднимает системный VPN.

Это не реализация Telegram или MTProto с нуля. Авторизация, чаты, хранение данных, медиа и основной интерфейс взяты из Mercurygram/Telegram Android. Ниже перечислены именно изменения этой ветки относительно стабильного Mercurygram `12.10.0.1`.

## Что я сделал

### 1. Push-уведомления с упором на экономию батареи

- Вернул нативный Firebase Cloud Messaging: он автоматически используется, если внешний UnifiedPush-дистрибьютор недоступен.
- Сохранил UnifiedPush/WebPush и встроенный FCM-дистрибьютор Mercurygram как резервные или явно выбираемые варианты.
- Если Firebase и UnifiedPush недоступны, приложение включает штатное фоновое соединение Telegram как последний резервный вариант.
- Убрал лишние периодические пробуждения `NotificationRepeat`, когда keep-alive и фоновое соединение не используются.
- Добавил диагностику регистрации push, резервного режима и состояния соединения.

Клиент не запускает отдельный бесконечный foreground service только ради ожидания сообщений. Надёжность push всё равно зависит от Android-прошивки, установленного UnifiedPush-дистрибьютора и ограничений Telegram для неофициальной подписи APK.

### 2. VLESS внутри приложения

Я встроил [sing-box/libbox](https://github.com/SagerNet/sing-box) и добавил два режима подключения:

- **App-only VLESS** — основной режим. sing-box запускается внутри процесса приложения, открывает SOCKS5 только на `127.0.0.1`, а Telegram MTProto направляется в этот локальный прокси. Системный трафик Android не меняется, VPN-разрешение не требуется, TUN-интерфейс и отдельный Android-сервис не создаются.
- **Built-in VPN/TUN** — отдельный режим, который пользователь запускает явно и для которого требуется стандартное разрешение Android VPN.

Дополнительно реализовано:

- импорт ссылок `vless://`;
- несколько профилей с выбором активного и удалением ненужных;
- отдельные случайные логин и пароль для loopback SOCKS5;
- запуск app-only прокси при открытии приложения и остановка после ухода в фон;
- защита fail-closed: пока sing-box не готов или уже остановлен, MTProto закреплён за неслушающим `127.0.0.1:1` и не может незаметно перейти на прямой IP телефона;
- настройки sing-box для умеренного потребления ресурсов: `GOMAXPROCS=2`, `gc_percent=200`, без mux, DNS sniff/hijack только для `udp/53`;
- корректное закрытие libbox и TUN-дескрипторов при остановке.

VLESS-профили не лежат в исходниках и не встраиваются в обычный APK. Они хранятся в атомарно обновляемом файле приложения, зашифрованном ключом из Android Keystore:

```text
/data/user/0/it.belloworld.mercurygram.beta/no_backup/battery_vpn/vless_profiles.enc
```

Обычное обновление APK сохраняет профили. Очистка данных или удаление приложения удаляет их.

### 3. Отдельная hardened-сборка

Добавил build type `hardened` для пакета `it.belloworld.mercurygram.beta`:

- отключены `debuggable` и JNI debug;
- включена минификация;
- запрещены backup/restore, cleartext traffic и захват воспроизводимого приложением аудио;
- удалены неиспользуемые и избыточные разрешения;
- внутренние activity, receiver и service закрыты от внешнего запуска там, где экспорт не нужен;
- чувствительные значения VLESS и локального SOCKS хранятся через Android Keystore;
- из debug-логов удалены push-токены, адреса endpoint, телефоны, имена контактов и локальные пути к медиа;
- добавлен CI-скрипт `scripts/check-sensitive-logs.sh`, который блокирует известные шаблоны небезопасного логирования;
- приватные параметры сборки не хранятся в репозитории; локально используются игнорируемые файлы, а CI получает значения только из GitHub Environment Secrets.

### 4. Аккаунты, стабильность и диагностика

- Увеличил технический лимит локальных аккаунтов с 8 до 32 одновременно в Java- и native-части.
- Исправил работу JNI из native network thread: поток самостоятельно attach/detach-ится к JVM и больше не использует чужой закешированный `JNIEnv *`.
- Исправил выделение native `ConnectionsManager` для аккаунтов выше восьмого, чтобы они не попадали в один и тот же слот.
- Добавил локальные настройки уведомлений для каждого аккаунта: включение, звук и вибрация.
- Добавил экраны нагрузки и диагностики: CPU-время процесса, заряд батареи, активные аккаунты, состояние соединения, push-режим и размер базы каждого аккаунта.
- Диалог `AUTH_KEY_DROP_*` теперь показывает номер проблемного аккаунта и выходит именно из него, а не из аккаунта, открытого на экране.

### 5. Небольшие прикладные доработки

- Разрешил скриншоты на экранах приложения, включая те места, где Telegram устанавливал `FLAG_SECURE`.
- Исправил установку APK, открытых из чатов, и передачу APK в системный установщик обновлений.
- Расширил «Данные сообщения» для видео и кружков: MIME-тип, длительность, разрешение, кодек, дата записи и полный локально прочитанный отчёт MP4/QuickTime metadata.
- Для телефонных номеров добавил действия «Позвонить» и «Перевести». Оба передают нормализованный `tel:` URI системному Android resolver, поэтому пользователь сам выбирает звонилку или банковское приложение.

## Как устроен основной сценарий

```text
Telegram MTProto
      │
      ▼
127.0.0.1 + SOCKS5-аутентификация
      │
      ▼
sing-box/libbox внутри процесса Mercurygram
      │
      ▼
VLESS-сервер
```

App-only VLESS обслуживает только сетевые подключения Telegram. Уведомления приходят независимо через Firebase или выбранный UnifiedPush-дистрибьютор, поэтому ради них не нужно держать VLESS и Telegram-процесс активными постоянно.

## Сборка

Проверенная конфигурация:

- JDK 17;
- Android SDK 35 / Build Tools 35.0.0;
- Android NDK `27.2.12479018`;
- CMake `3.22.1`;
- Go для проверки конфигов sing-box;
- минимальная версия Android для arm64-сборки — API 24.

Создайте игнорируемый файл `API_KEYS` с собственными [Telegram API credentials](https://core.telegram.org/api/obtaining_api_id):

```properties
APP_ID = 123456
APP_HASH = 0123456789abcdef0123456789abcdef
```

Сборка hardened APK для `arm64-v8a`:

```bash
./gradlew \
  -PMG_BUILD_TAG=12.10.0.1 \
  :TMessagesProj_App:assembleAfatFdArm64Hardened
```

Готовый APK:

```text
TMessagesProj_App/build/outputs/apk/afatFdArm64/hardened/afatFdArm64.apk
```

Перед Android-сборкой Gradle запускает `scripts/check_sample_config.sh`: скрипт собирает sing-box `v1.13.14` и проверяет оба примера конфигурации командой `sing-box check`.

Проверки безопасности можно запустить отдельно:

```bash
scripts/check-sensitive-logs.sh
```

## Ограничения

- Нативный Firebase и встроенный FCM-дистрибьютор требуют Google Play Services. На устройствах без них следует выбрать отдельный UnifiedPush-дистрибьютор.
- App-only VLESS работает только для Telegram и только пока приложение активно. Это намеренное поведение, а не замена системному VPN.
- Поддержан импорт `vless://`; это не универсальный GUI для всех протоколов sing-box.
- Лимит 32 аккаунта остаётся фиксированным из-за массива singleton-объектов в Telegram Android.
- Скриншоты разрешены намеренно. Пользователь должен учитывать это при работе с секретными чатами и чувствительными данными.

## Безопасность репозитория

Нельзя коммитить:

- `API_KEYS` и `local.properties`;
- keystore и пароли подписи;
- Telegram-сессии, базы данных и auth keys;
- push-токены, OAuth-токены и логи с личными данными;
- Firebase service-account JSON и серверные FCM credentials. Android client
  config намеренно открыт: те же значения неизбежно находятся внутри APK;
- реальные VLESS-ссылки и пользовательские профили.
